## Preserve snapshot reads and handle missing release tags explicitly

When publishing a new DuckDB snapshot, keep retired snapshot files available
while an AnalyticsSnapshot handle refers to them. Cleanup marks a file retired
and deletes it only after the final handle is dropped. If a requested versioned
snapshot has disappeared, return an error and never fall back to the mutable
live database.

**Rationale:** retained or concurrent readers must observe the immutable
snapshot they received. Deleting it early breaks that contract; substituting
the live database silently changes query results. The lease is internal and
the serialized descriptor keeps its existing path, snapshot_id, and immutable
fields.

For release-scoped scans, skip repositories that do not contain the requested
tag. If none of the discovered repositories contains the tag, return an error
and write no metrics. The lower-level changed-files helper reports a missing
tag as an error.

**Rationale:** treating a missing tag as an empty diff can create misleading
zero-change metrics. Per-repository skipping still lets a multi-repository
scan handle the repositories where that release exists.

## Build the production UI in each Tauri bundle job

Point Tauri's `frontendDist` at `../ui/dist`. Its `beforeBuildCommand` must
install from `ui/pnpm-lock.yaml` with `--frozen-lockfile`, run the production
