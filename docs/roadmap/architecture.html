# Architecture ## Current State - Application stack: Rust + Tauri (on-prem only). - Analysis model: bead/plugin pipeline with mandatory sanitizer pre-processor. - Storage model: - Raw ingestion is stored in the shared storage crate's SQLite WAL database with transactional writes, ordered prefix scans, retention, and deletes. - Promotion receipts and analytical history are stored in DuckDB for aggregations, scoring, and ranking; the native library is an official checksum-verified prebuilt binary. - Security controls: - RBAC admin-only access for sensitive operations. - Sanitization at pre-processing and telemetry persistence/query boundaries. - Storage boundary primitives enforce route semantics (ingestion vs analytics). - Runtime controls: - The default ingestion backend is SQLite WAL; explicit Badger sidecar settings remain opt-in, and removed Sled configuration fails with an actionable migration error. - Backend-aware ingestion transport supports: - `inproc://` development/test sidecar simulation. - `unix://` sidecar socket transport. ## Destination Final State - Strict dual-layer architecture (no workload mixing): - Ingestion layer: - SQLite WAL is the embedded ingestion backend. - Serialized writers, ordered key-prefix scans, and transactional acknowledgements preserve append and replay behavior. - Short-term retention with TTL prune and roll-up. - Analytics layer: - DuckDB for read-heavy historical analytics only. - Snapshot/replica-style read model for zero-contention query behavior. - Long-term compressed retention by release partitions. - Promotion lifecycle: - Asynchronous event promotion from ingestion tier to analytical marts. - Deterministic, idempotent promotion checkpoints and auditability. - Scoring and ranking: - Versioned, audited scoring weights. - Baseline-normalized committer scoring (delta complexity) across legacy and greenfield repos. - PR ranking based on risk, velocity, and policy compliance. - Governance and quality gates: - Non-bypassable storage boundary guards across runtime/admin APIs. - Coverage and validation gates enforced in CI/CD with >=80% core architecture line coverage. ## Gap to Close - Add and verify the one-time audited migration from existing Sled stores to SQLite before allowing those installations to start. - Retire Tauri/GTK only after the GTK-free native shell meets required parity and installed-app validation gates. - Add sidecar health checks, retry/backoff strategy, and observability metrics for queue depth and promotion lag. - Complete snapshot materialization/rotation mechanics for analytics read isolation.
